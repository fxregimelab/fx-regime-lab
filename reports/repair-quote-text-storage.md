# Malformed-response text preservation

SQL integration review found that PostgreSQL cannot materialize actual NUL or lone-surrogate characters as TEXT. The pure capture layer previously allowed those characters in malformed-response diagnostics or retained headers, so otherwise valid capture envelopes could fail to archive.

Capture now escapes those unsupported characters in JSON keys and string values, malformed raw text and allowed headers, and records text_storage_escaped. PostgreSQL inspection can decode unrelated strings while traversing a JSON object, so merely escaping outer text was insufficient; real SQL probes reproduced both key and value failures. The retained diagnostic shows a visible backslash-uXXXX sequence. The original response-byte hash and size do not change. Numeric source values stay exact, but exceptional strings and keys are explicitly sanitized rather than claimed lossless. A resulting key collision rejects capture. A malformed original body remains diagnosed as malformed even if sanitation makes its retained text parseable.

The validator rejects forged manifests that still contain unsupported actual characters, including when their hashes were recomputed. No quote is promoted or repaired by this sanitation. Six new regressions cover malformed NUL text, NUL/surrogate headers and JSON keys/values, collision rejection and forged outer/nested controls. All 148 integrated capture/reference/writer tests pass; scoped Ruff and strict MyPy pass. The parent independently reverified real PostgreSQL round trips for malformed raw text and exceptional JSON values and keys; the complete six-group storage verifier passed.

GitNexus still reports the capture and validator symbols as unindexed / UNKNOWN. The actual inspected consumers are the pure reference constructor and the two new central writer functions. This is a storage compatibility repair to sanitized evidence, with the amendment recorded in both the capture and storage contracts.
