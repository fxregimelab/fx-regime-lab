# Saved administrative read: central writer and real database

Parent verification on 29 September 2026 passed against task-local PostgreSQL 17.11 in an isolated, disposable database. The test used the two pinned NSDL Latest/Monthly source reports and the independently built original-reference oracle. It archived both original captures, both complete parse records and both retained code artifacts through `pipeline/src/db/writer.py`, with exact insert and retry receipts. It then requested saved reads through that same writer and loaded their exact named originals using service-role SQL projected by a small local transport adapter.

The full read retained all 19 original memberships. A narrower read still retained all 19 in its complete parse references, with nine present only as supporting history. The loader's decoded manifest matched the exact saved database document. Four changes to real SQL query results—missing parse page, duplicated parse row, changed saved read hash and wrong artifact kind—were rejected by the writer with bounded errors; an unchanged load passed after each. A later membership withdrawal appeared in a new read with its event and head, while both earlier reads loaded byte-for-byte unchanged. A real saved clock-inconsistency outcome loaded from its one saved row and made no original-document queries.
