# D03 provider timing research

Research checked 29 September 2026. This is a source and code review, not a live API capture, historical vintage export, or acceptance of D03/D06. No credentials or production data were used.

## What the current code can prove

`pipeline/universe.json` currently configures `DGS2` against `ECBDFR`, `IRLTLT01JPM156N`, and `INDIRLTLT01STM`. In `pipeline/src/fetchers/yields.py`, `_fred_latest_async` requests one observation in descending observation-date order but returns only `value`; the response's `date`, `realtime_start`, and `realtime_end` are discarded. The sync FRED paths also take only the last non-null scalar. Yahoo fallbacks likewise retain only the last close. The result is a map of bare numbers. `_rates_bucket_freshness` in `pipeline/src/validation/ingestion_buffer.py` then scores rate freshness using the **spot** observation date. A fresh spot can therefore make an old monthly rate appear fresh. D03 in `docs/REPAIR_REGISTER.md` remains open.

The historical FRED loader (`pipeline/src/backfill/fred_historical.py`) calls `fred.get_series` and stores only `series_id`, observation `date`, and `value` in `historical_yields`. The simulation reader selects those same three fields. No row establishes when that value or that revision was available to a past decision. This is the separate D06 point-in-time gap.

## Provider facts that affect the repair

| Feed in this checkout | Observation date and frequency | Release or availability evidence | Consequence |
| --- | --- | --- | --- |
| [DGS2](https://fred.stlouisfed.org/series/DGS2), [DGS10](https://fred.stlouisfed.org/series/DGS10) | Daily H.15 Treasury constant-maturity yields. | The [Federal Reserve H.15 page](https://www.federalreserve.gov/releases/h15/) says the release is posted Monday–Friday at **4:15 p.m.** and is absent on holidays/Board closures. This is a scheduled publication time, not proof that FRED served a particular observation at that instant. | Keep the observation date and actual receipt time. Do not equate the H.15 schedule with the response's witnessed availability. |
| [T10YIE](https://fred.stlouisfed.org/series/T10YIE) | Daily breakeven inflation series derived from nominal and inflation-indexed Treasury yields. | Its FRED page gives a series-level “Updated” time; that is not a historical timestamp for every observation/revision. | Capture the selected observation and its FRED real-time fields; do not borrow DGS2 timing. |
| [ECBDFR](https://fred.stlouisfed.org/series/ECBDFR) | Daily, seven-day ECB deposit-facility **overnight policy** rate. | FRED identifies the ECB's Key ECB Interest Rates release and displays a current update time. It does not establish an observation-specific historic intraday release from the scalar now stored. | Its date describes a policy-rate observation, not a matched two-year market yield. Preserve the actual release witness if obtained separately. |
| [IRLTLT01JPM156N](https://fred.stlouisfed.org/series/IRLTLT01JPM156N), [INDIRLTLT01STM](https://fred.stlouisfed.org/series/INDIRLTLT01STM) | OECD **monthly** ten-year government-bond yields. A present-day page update is not a per-observation historic release time. | A universal 36-hour freshness rule is unsuitable. Age, release lag, and acceptable staleness require an explicit policy per series and frequency. |
| [IRLTLT01DEM156N](https://fred.stlouisfed.org/series/IRLTLT01DEM156N), [IRLTLT01ITM156N](https://fred.stlouisfed.org/series/IRLTLT01ITM156N) | OECD monthly ten-year German and Italian yields used as fallbacks or the Bund–BTP context. | Both currently show August 2026 and a 15 September 2026 FRED update; no next release date is listed. | Preserve each leg's independent timing before subtracting them. A spread with mixed observation months or vintages must be identifiable. |
| [IRSTCI01JPM156N](https://fred.stlouisfed.org/series/IRSTCI01JPM156N) | OECD **monthly** Japanese call-money/interbank rate, described by FRED as an immediate rate under 24 hours. | The page currently shows August 2026, FRED update on 15 September, and no next release date. | The fetcher's “BoJ policy rate” label is a proxy description; neither the observation month nor the scalar proves an actual BoJ policy decision release. |
| [ECBASSETSW](https://fred.stlouisfed.org/series/ECBASSETSW) | Weekly ECB assets in millions of euros; the current page shows an observation dated 18 September and an update on 22 September. | FRED names the ECB Weekly Financial Statements release. The four-day separation on the current page illustrates why observation date and publication/update date must remain separate. | A weekly value cannot inherit daily spot freshness. |

FRED's [observations endpoint](https://fred.stlouisfed.org/docs/api/fred/series_observations.html) exposes `date`, `value`, `realtime_start`, and `realtime_end`. Its default real-time period is **today**. FRED's [real-time-period guide](https://fred.stlouisfed.org/docs/api/fred/realtime_period.html) explains that historical real-time periods represent what was known then; observation dates and real-time dates have different meanings. The [vintage-dates endpoint](https://fred.stlouisfed.org/docs/api/fred/series_vintagedates.html) lists dates when new or revised values changed the series, excluding releases that left the series unchanged. The [release-dates endpoint](https://fred.stlouisfed.org/docs/api/fred/release_dates.html) lists release dates, but neither a date-only vintage nor a release calendar entry supplies a verified intraday response time. FRED's `last_updated`/page “Updated” is series-level metadata, not a substitute for the release time of a selected old observation.

## Exact missing evidence

1. **Every live rate leg:** selected observation date/period, units and frequency, provider and source-series ID, response receipt time in UTC, source `realtime_start`/`realtime_end` where FRED supplies them, and an immutable source-response or observation-vintage fingerprint. A timeout or empty response must not reuse a prior scalar under a new receipt time.
2. **Release time:** a per-observation, per-vintage `released_at` only when an authoritative release artifact or timestamp proves it. Keep unknown when the provider offers only a release date or scheduled time. Record the source and precision of any release claim. FRED's current page update and the H.15 schedule must not be silently assigned to historic rows.
3. **Historical replay:** actual FRED/ALFRED real-time queries and coverage checks for *each* configured series and date. The documentation shows an API route, not that every needed series has a complete vintage history. Present-day revised values in `historical_yields` cannot become past-known values by adding a date column after the fact.
4. **Non-FRED fallback:** Yahoo close rows need their own bar timestamp/session, retrieval time, source identity, and revision policy. A switch from FRED to Yahoo must remain visible. No equivalent historical point-in-time guarantee was established in this review.
5. **Decision and freshness rules:** compare each source's evidenced availability and receipt to the decision cutoff; score age from that source's own observation/release policy, with frequency-aware tolerances and explicit missing/unknown states. A stale monthly or weekly observation must not pass because spot was fresh. Matching the economic tenor/market definition remains D01/D02 work.

**Narrow next step:** define and test a dated rate-observation contract at the FRED/Yahoo acquisition boundary, then make rate health consume those observations. Keep historical replay labelled current-vintage reconstruction until the series-by-series vintage and release audit is complete. This report supplies source semantics; it does not mark the defects repaired.
