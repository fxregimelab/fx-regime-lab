# Quote capture repair — packet 14

The new pure capture module turns supplied response bytes into a sanitized, fingerprinted page manifest. It performs no provider request, clock read, file access or database write. Its only current consumer is the separate research reference constructor. The shared interface and acceptance limits are in [the contract](../docs/QUOTE_CAPTURE_CONTRACT.md).

Every page binds the locked pair, explicit candidate provider instrument, exact UTC-day nanosecond window, page index, request parameters, request and receipt timestamps, HTTP status and allowed response headers. Initial requests require the full ordered-query contract. Continuations retain a cursor hash rather than its opaque value. Valid next URLs must have the approved HTTPS origin, exact pair path and consistent allowed query parameters. Hostile URLs become explicit acquisition defects and are never followed.

The manifest preserves the original byte count and SHA-256 fingerprint alongside the redacted body and its separate fingerprint. Its final hash covers all retained metadata. Decimal JSON parsing and deterministic number serialization preserve source precision without using the ambient Decimal context. Duplicate keys, nonfinite JSON constants, excessive nesting and malformed UTF-8/JSON remain explicit defects. An original fractional or exponent timestamp token is flagged before normalization could disguise its type.

Configured secret literals and URL-encoded forms are redacted. Sensitive object fields are replaced; sensitive request parameters and unsupported headers are discarded. Cursor values are redacted from retained value text, while schema keys survive accidental overlap with short opaque tokens. Redaction that would merge distinct keys rejects the capture. Hashes establish internal consistency, not source authenticity: someone able to replace the entire record could recompute them. Unknown secrets in arbitrary content cannot be certified absent by this module.

Integration review found and repaired two nontrivial defects before acceptance: short cursor tokens could corrupt JSON key names, and numeric normalization could turn an invalid timestamp representation into an apparently valid integer. Regression tests now cover both. Arithmetic resource limits and completed-day acquisition timing were then made explicit in the shared constructor contract.

GitNexus pre-edit checks returned target-not-found / UNKNOWN for the three new public functions. There were no indexed existing callers. The constructor and focused tests are the inspected consumers; this is not a claim of an up-to-date repository-wide graph.

## Verification and limits

Packet-fourteen parent capture tests passed 82 cases, including altered records, independently recomputed malformed manifests, exact nanoseconds, decimal precision, request bounds, nested credentials, lowercase percent escapes, redaction collisions, hostile pagination, immutable input copies and timestamp normalization. Scoped Ruff and MyPy pass. Parent independently reverified 25 constructor tests and all 107 integrated capture/constructor tests, including 130 exact Fraction comparisons. The full pipeline regression gate passes (848 tests collected), full Ruff passes and full MyPy passes for 190 source files. No frontend or database source changed in this packet.

All data in these checks is synthetic. No market series was acquired or accepted. This packet does not implement durable page storage, HTTP pagination, append-only maturity/acceptance events or evaluation integration. A completed deterministic construction remains provisional and validation-ineligible. Body size is checked after bytes reach this function; the eventual transport must enforce its streaming size limit before allocation. The fixed 128-digit/exponent arithmetic envelope is a resource constraint, not an empirical market-quality threshold. Provider entitlement, all-three-pair availability, completeness near daily boundaries, holidays, revision policy and actual price qualification remain open work.
