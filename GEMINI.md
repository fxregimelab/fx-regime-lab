## Development Conventions & Hard Rules

### 1. Research Integrity (The Alpha)
- **Immutable Calls**: Every regime call generated by the pipeline MUST be timestamped and never modified. This is the out-of-sample track record.
- **Validation First**: Every signal must have a corresponding validation entry (T+5, T+20) to prove efficacy.
- **Strict Typing**: Strict `mypy` is required for all pipeline code. We prioritize mathematical correctness over development speed.

### 2. Implementation Delegation (The Agent)
- **Cursor Agent CLI**: Complex implementation, auditing, and debugging tasks should be delegated to the Cursor Agent via CLI (`agent --print "..."`) to ensure precision and cross-file consistency. All agent outputs must be verified by the Engineering Chamber.

### 3. UI/UX Standards (Academic Minimalism)
- **Aesthetic**: Swiss-style, high-density, monochrome. Pure black (`#000000`), white text, sharp 1px borders.
- **No Fluff**: Strictly NO soft shadows, NO decorative animations, NO "cinematic" transitions.
- **Information Density**: Maximize data points per square inch. Use `tabular-nums` for all financial figures.
- **Math Rendering**: All formulas must be rendered using KaTeX to maintain institutional rigor.
- **Transparency**: Always show the inputs (Layer 2 signals) alongside the output (Layer 1 regime).

### 3. Data Flow
- **Surgical Writes**: All Supabase writes MUST go through `pipeline/src/db/writer.py`.
- **Fallbacks**: Never assume external APIs (FRED, CFTC) are stable. Implement explicit `None` handling and data resilience.
