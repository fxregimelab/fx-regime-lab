# Private historical fundamental vintages — bounded contract

Owner scope: private FX research, 1 October 2026. This packet advances R2 by preserving and auditing selected historical ALFRED snapshots. It does not put macro features into the existing backtests or qualify a trade.

The coordinator witnessed the official ALFRED graph's CSV download link. The graph-export route is first-party UI evidence, not a documented API guarantee. Every response must establish its requested vintage through the exact two-column header `observation_date,SERIES_YYYYMMDD`. A current FRED CSV, wrong vintage, extra/transformed column or unrecognized series is rejected. Initially allow only CPIAUCSL and DGS2; both are USD observations. Do not imply coverage of the other six currencies or a matched international yield spread.

Require canonical dates, strictly increasing distinct observation dates inside the named request window, no observation after its vintage or receipt date, and finite numeric values. Keep source missing cells as null, never zero. CPI index values must be positive; a yield can be negative. Request the original level transformation only. Historical units/frequency/seasonal-adjustment metadata remain unqualified unless separately captured for that vintage; current metadata cannot silently certify an old snapshot.

Capture only explicitly named series/vintage/window requests: at most twelve distinct requests and at most thirty-one years per request. Preserve successful, failed and truncated responses with unique original files, URL, status, UTC receipt, completeness, byte count and SHA-256. Cache and saved evidence reuse check request identity, path boundary, receipt hash and body hash. Corruption fails without a quiet replacement request. Equal duplicate snapshots count once; conflicting values for the same series, vintage and observation fail the series audit. Compare revisions only over common observation dates; absent and missing values remain distinct.

An as-of **calendar-date audit** may select the newest captured vintage no later than that date. It must not use a later vintage just because the observation period is old. It is not an intraday availability selector or a forecasting feature. Vintage dates, observation dates, source release times, archive ingestion times and current receipt times remain separate. No midnight, timezone or next-day availability is invented. ALFRED's typical one-business-day update delay is not a guaranteed upper bound; backfilled archives do not prove contemporaneous receipt.

The report and dashboard show a separate historical-fundamental audit with actual vintage coverage, revisions, original provenance, missing currencies and unknown release times. Dashboard refresh only reads saved evidence. Existing candidates, price backtests, session studies, AI review and bid/ask evidence remain unchanged. Offline replay recomputes the audit from pinned original responses. Expectations/surprises and all model/probability claims remain unqualified.

Acceptance requires deterministic future-vintage and revision controls, strict parser/capture failures, source-specific actual captures, independent original/new report comparison, offline replay, final pipeline tests/lint/types, UI regressions and authenticated desktop/mobile checks. R2 remains open until the required currency legs, release/availability evidence, metadata and expectations have their own proof.
