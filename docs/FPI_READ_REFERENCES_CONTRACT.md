# Complete retained FPI read references

Packet28 parent contract, 28 September2026. This is a required loader primitive for the complete saved-read layer proposed in reports/repair-fpi-decision-storage-design.md. It does not claim a database snapshot, source authenticity, acquisition order, executed-code trust or consumer eligibility. The full repair goal and those dependent requirements remain open.

## Interface

Extend pipeline/src/research/fpi_parse_record.py with a frozen FpiReadReferences(reference_sha256: str, document_json: str) record and build_fpi_read_references(*, captures: tuple[FpiCapture,...], records: tuple[FpiParseRecord,...]) -> FpiReadReferences. It produces compact references only after validating the complete retained documents. Do not edit the existing v1 types or reinterpret their hashes. No I/O, network, DB, source parsing or artifact execution. A directly constructed FpiReadReferences is an assertion; consumers must compare against this rebuilding boundary with retained originals, not trust the class or supplied hash.

Both arguments are exact tuples with at most2048 entries each, checked before traversal/dedup. Elements must have exact existing types and exact string identity/document fields. Copy primitive fields before validation. Duplicate identical entries deduplicate deterministically; the same capture ID with different bytes or parse ID with different hash/document rejects before any winner is selected. No capture may be missing or unused: distinct supplied captures exactly cover the capture dependencies of distinct records. Empty inputs yield an empty canonical bundle. A captured report may support many different parser results; failed and successful results remain distinct under their parse identities.

Preflight all exact types, individual document caps (capture7000000, parse4000000 ASCII characters) and combined unique original-document budget64000000 ASCII bytes before decoding/hashing those documents. Test exact bounds with a small controlled budget and actual overlong text before parse. Duplicate documents do not increase the unique byte budget, but input count limits apply before dedup. Do not encode an unbounded input just to measure its size. Maximum distinct memberships20000, maximum canonical reference document16000000 bytes. Reject overflow before building the aggregate document; never truncate, silently discard duplicates with different content or return a partial success. Limits are explicit engineering limits, not provider completeness proof.

Validate each unique full capture exactly once with existing validate_fpi_capture. Decode its canonical JSON once for metadata. Validate each unique full parse exactly once through existing _record_parts, retaining its checked metadata and complete member/date set. Avoid restore_fpi_parse_record in a per-record loop because that repeatedly validates shared raw capture bodies. Preserve ALL cross-capture checks from actual restore semantics: matching capture identity, parse recorded_at>=retrieved_at, successful result requires HTTP200 and the canonical observation definition, every reporting date<=capture receipt's India calendar date. No timezone database needed: Asia/Kolkata here is fixed UTC+05:30 as in the accepted selector. Do not fabricate stored_at, source release times, trust states or candidate membership scope.

## Canonical output

Compact ASCII JSON using ensure_ascii=True, sorted keys, separators(',',':'), no NaN/Infinity. document_json has exactly version='fpi-read-references-v1', captures, parses. reference_sha256 is SHA256 of the exact ASCII bytes. Arrays sort captures by capture_sha256, parses by parse_id. Per-parse memberships retain ascending reporting-date order from the accepted record codec. All distinct members of a parse appear, even if a future date-scoped reader uses only one as a candidate. This bundle does not choose candidates or recursively expand a future scope.

Capture entry fields exactly: capture_sha256, document_size, source_url, requested_at, retrieved_at, http_status, body_size, raw_sha256. document_size is the exact original canonical capture document length. Times and other metadata come from that validated document unchanged; source URL is the accepted fixed endpoint. Do not include body_base64 or body bytes.

Parse entry fields exactly: parse_id, record_sha256, document_size, content_sha256, capture_sha256, parser_sha256, definition_version, recorded_at, failure_reason, memberships. document_size is the exact original canonical parse record length. memberships contains exact reporting_date, value_sha256, membership_id and source_evidence_sha256 for every validated day. No raw INR/source documents in the compact output; their identities and complete membership list bind back to the retained record. A future loader still retains/accesses original documents when deriving numeric inputs; this compact bundle is not a standalone numeric input or permission to skip source verification.
