# Price observation archive contract

This archive records what a provider returned and when it was retrieved. It does not certify a final market close or an executable price. Daily-window anchoring is unresolved for the current source adapters; Massive's ET prose and generic timestamp sample do not establish FX daily midnight boundaries. Do not choose ET/UTC/17:00 NY canonical sessions by assumption. See reports/repair-price-provider-research.md.

## Observation payload

`SpotBar` gains nullable `provider`, `instrument`, `retrieved_at`, `provider_timestamp`, `session_timezone`, `session_definition`, `window_start`, `window_end`, plus a JSON `provider_metadata` dictionary and nullable `volume_source` / `volume_instrument`. All timestamps are aware UTC instants or null. Missing historical metadata is never backfilled from the current clock. Requests-based adapters capture retrieval immediately after the response returns, before JSON parsing. Yahoo adapters capture the library download-return time before our frame transformation; this is not the raw HTTP receipt because yfinance has already transformed the response. Parsers receive that captured time; raw epoch/index time and an explicitly labeled provider date are retained. Polygon's working date uses the UTC date of raw window start solely as a stable timestamp label, with metadata `date_label_policy=timestamp_utc_date`; it is not a verified canonical session. AV and Yahoo retain provider date labels and timezone metadata without fabricating a window end. CME proxy volumes carry a separate source/instrument.

Archive rows are JSON objects containing exactly pair,date,open,high,low,close,volume and the metadata fields above. Prices must be finite positive JSON numbers with valid OHLC ordering; volume finite nonnegative; date strict YYYY-MM-DD; pair one of EURUSD/USDJPY/USDINR. Provider is polygon, alphavantage or yahoo; instrument nonblank; retrieved_at is required aware timestamp. Other timestamps optional. `provider_metadata` contains only parser-whitelisted nonsecret response identity/session facts. It must be an object. Allowed metadata keys: date_label_policy,response_ticker,response_status,request_id,adjusted,raw_timestamp_ms,provider_timezone,last_refreshed,from_symbol,to_symbol,index_timezone,raw_index. Values are JSON scalar strings/numbers/booleans/null, never nested containers. Unknown session/window fields remain null.

`public.append_price_observations(p_observations jsonb)` accepts an array, validates every item, and appends atomically to private append-only `price_observations`. Store id(bigint), pair,date,provider,instrument,retrieved_at, observation(jsonb), payload_hash. Exact repeated payload is idempotent; a new retrieval or corrected value creates a new observation. Canonical hashing must normalize numerically equal JSON, like existing publication hashing. JSON contains no operational credentials. Reject invalid, future retrieval/provider timestamps, timestamps lacking offsets, unsupported pair/provider, malformed prices, unknown keys and batches larger than 5000. Optional window start/end must both exist or both be null; when present end must exceed start, but the archive does not infer completion. A future window end is allowed for an explicitly open observation; retrieval must not precede window start. Unknown provider_timestamp remains null.

RPC returns JSON with `observation_ids` in input order (including repeated IDs), `inserted_count` and `existing_count`. Lock/unique hash handles simultaneous duplicate retries. Batch failure rolls back all inserts. Service role may execute and read; anonymous/authenticated cannot read or execute; direct writes/update/delete/truncate denied to application roles. Immutable triggers apply, fixed search paths and explicit grants.

No archive row automatically writes `historical_prices`. Existing stored closes and their v2 evaluations remain unchanged. Automatic promotion awaits a verified canonical window/availability policy or an explicit UTC aggregation built from timestamped shorter intervals. This is an open part of V08/P01, not a waived requirement.

Python `writer.archive_price_observations(observations: Sequence[Mapping[str,Any]]) -> dict[str,Any]` sends one RPC, verifies the response counts/IDs, never strips fields or falls back to a bare upsert. Pure `src.core.price_archive.prepare_price_observations(spots, *, as_of:date, cutoff:datetime) -> PriceArchiveBatch` serializes valid recorded metadata, returns observations and missing/invalid counts. No invented retrieval time for old SpotBar fixtures. Archive lifecycle callers must propagate write errors and report absent/unknown session evidence as degraded, not complete validation.

Acceptance: host timezone independent provider parsing; source metadata survives core mapping and volume proxy injection; identical retry/concurrent inserts resolve same ID; revised prices/new retrieval preserve originals; one invalid batch item rolls back all; private roles denied; no historical_prices mutation; exact JSON and Python writer payloads pass actual PostgreSQL; inference excludes future bars; missing mature outcomes become operationally visible. Primary source research and final-close acquisition remain separate evidence gates.

Preparation counts: PriceArchiveBatch contains observations, missing_metadata_count, invalid_count, future_count and unknown_session_count. Provider timestamps must not follow their recorded retrieval. A zero unknown-session count is not validation eligibility or finality. The current adapters retain transformed row metadata; full raw-response envelopes and request manifests remain a separate open requirement.

## Remaining price qualification work

The next acquisition work must produce evidence, not a guessed clock rule:

1. Preserve sanitized request parameters and full response identity/hash alongside transformed rows. Keep API keys and authorization headers out of evidence payloads. Record source/client versions and any known entitlement without inferring them from a successful response.
2. Either establish a provider-specific daily boundary from reliable source evidence, or build a separate fixed UTC series from timestamped intraday observations. For a constructed series, test interval membership, duplicates, gaps, weekend closures, missing quotes and late corrections. Do not rename mixed provider daily bars as that series.
3. Freeze an eligibility and revision rule. A past date, known timezone or non-null window does not prove completeness. Track unresolved coverage separately from completed observations and keep later corrections append-only.
4. For executable-trade research, select entry evidence available after the actual publication timestamp, with an explicit bid/ask, latency and cost convention. Current publication-snapshot-v2 measures saved-price movement and cannot be retroactively upgraded into that claim.
5. Introduce any changed measurement as a new evaluation version. Preserve existing calls, observations and evaluations, and produce a record-by-record reconciliation before publishing revised results.

These are requirements under V08/P01 and the frozen research contract. Provider access, calendar evidence, historical provenance and release observation remain unverified until their own checks pass.


## Reference-series acquisition design

The primary-source review in [the acquisition report](../reports/repair-price-acquisition-research.md) recommends a separate fixed-UTC midpoint series from timestamped bid/ask observations. It is a proposed implementation contract, not an existing acquired series. Quote snapshots must retain page and occurrence identity: timestamp alone is not an event ID or a correction link. Page failure, unresolved gaps or ambiguous boundary prices must prevent qualification. Provider finality stays unknown; project acceptance is an append-only event bound to a policy version, exact input hash and acceptance time. A later correction cannot alter what was recorded or accepted earlier.

The remaining requirement is a qualified completed-window reference with explicit source, timing, coverage and revision rules. It is not an unprovable claim that a vendor will never revise a value. Implement the acquisition manifests, snapshot retention, deterministic construction and acceptance events before using the proposed series in a new evaluation version. Existing daily-provider observations and historical_prices rows remain distinct.
