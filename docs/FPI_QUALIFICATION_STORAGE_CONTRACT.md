# Durable FPI qualification contract v2

Frozen parent interface for packet27, 28 September 2026. Depends on accepted capture/parse storage and docs/FPI_QUALIFICATION_ORDER_CONTRACT.md. This layer records administrative qualification assertions. It does not authenticate source data, parser execution or historical decision visibility. ACCEPT alone never enables a feature. Protected recomputation, complete saved decision reads and consumers remain separate required work.

## Explicit staging decision

The execution-trust design in reports/repair-fpi-execution-trust-design.md requires successful protected recomputation for final SQL membership acceptance. Packet27 deliberately implements only the administrative action ledger first. Its ACCEPT means recorded intent, never verified eligibility. There is no eligibility field, publication path or consumer in this packet. This is a staged boundary, not fulfillment or removal of the trust requirement: the later protected acceptance/decision layer must validate exact parser verification and observed release approval independently for every candidate, including earlier ACCEPT events. Merely pointing to this event cannot satisfy that check. No synthetic verifier approval table or production bypass is allowed. Activation remains blocked until that integration is proven.

## Python boundary

Add only append_fpi_qualification(command: FpiQualificationCommand) -> dict[str, Any] to pipeline/src/db/writer.py, plus focused tests. Reconstruct the command through the existing strict canonical decoder and compare every original field/cache before acquiring a client; forged frozen records must fail. One RPC append_fpi_qualification(p_command_id text, p_document_json text) owns the transaction. Do not upload dependencies, fetch current heads or silently retry with a changed predecessor.

Successful receipt has exactly version, command_id, event_id, event_ordinal, recorded_at, event_document_json, inserted. Version is fpi-qualification-receipt-v2. inserted is an exact boolean, ordinal exact integer in the existing signed-bigint range, identities exact lowercase hashes. recorded_at is the exact canonical UTC string in the event document. Strictly decode event_document_json through existing v2 codec, compare event ID, ordinal, time and the entire embedded command against the frozen submitted command. Server witness structure is validated by that codec; the Python writer cannot authenticate its database read. Return a new plain receipt. Client/RPC/receipt errors expose static bounded messages without the original exception or payload. Local invalid input rejects before I/O. Preserve cancellation/base exceptions. No existing writer behavior changes.

## SQL storage

Forward migration supabase/migrations/20260928000012_fpi_qualification_storage.sql requires migrations10/11. Create private append-only public.fpi_qualification_events with event_id primary key, command_id unique, command_document_json, event_document_json, event_ordinal unique bigint, scope, target, expected_prior_event_id nullable self reference, recorded_at timestamptz. Keep useful target/order index. Enforce one successor per (scope,target,coalesce(expected_prior_event_id,'')) including roots. The only append path is the security-definer RPC with fixed search path. No mutable current-head cache is needed: latest ordinal on target defines head. Original captures/parses remain unchanged.

Use a private bigint sequence for ordinals; gaps after rollback are allowed. Every qualification append takes the same transaction advisory lock (946027,1) before any current-head query or ordinal allocation. Hold it until transaction end. All writes are VOLATILE and require transaction_isolation=read committed; reject unsupported isolation explicitly. After the lock, queries get fresh snapshots. This serializes qualification commits across all scopes. Never order by server/client clock, parse ordinal or arbitrary hash. No client time/ordinal fields are accepted. Function-local lock_timeout is10s. Do not use a function SET statement_timeout as a claimed outer timer: the parent reproduced that it does not arm one. Caller connection/request setup must set statement_timeout before the top-level SQL command, in1..30000 milliseconds; the RPC checks inherited pg_settings.setting and rejects0 or greater than30000. Do not overwrite that inherited setting inside the function. The harness sets30s before invoking the top-level call and includes an actual outer cancellation control with a scratch delayed clock helper. No persistent global/session configuration change is made by the migration. The inherited-setting guard cannot prove that hostile nested SQL armed its timer; production PostgREST connection timeout configuration remains a separate release check, not certified by this local RPC.

Validate exact canonical ASCII command bytes (<=300000), unique keys, version, key set, types, reason/evidence hashes, expected predecessor, actions and basis using the accepted v2 contract. Python and SQL must agree, including booleans, empty/null, invalid date and duplicate basis. Command hash must match authoritative text. Unknown command fields reject. Evidence hash is a reference, not a fabricated trust attestation.

After lock, find an existing identical command first: exact retry returns its same event/time/ordinal/document with inserted=false, even if later heads changed. If none, resolve the target against actual retained evidence: membership must exist; value must occur in retained memberships; parser must exist as PARSER artifact; date must have retained memberships. Current target head must equal expected_prior_event_id, including explicit null root. Reject missing/wrong-scope/stale predecessor; no automatic rebase. A new accepted event has inserted=true.

RESOLVE uses one post-lock SQL statement to read the complete same-date candidate set, chosen member metadata and current membership/value/parser heads from committed rows. Probe candidate count at4097 and fail if more than4096 before an unbounded aggregate. Exact sorted basis must equal that full date set, including unqualified members and alternate parsers. Chosen membership belongs to it and its membership head is ACCEPT; value/parser heads are absent or ACCEPT. Store the exact three observed witness heads sorted (scope,target). If parse rows commit after this statement, this resolution keeps its original basis; a future complete view diagnoses STALE_RESOLUTION. Parse writers need not take the qualification lock. Non-date events have null witness.

Allocate ordinal after checks; sample private public.fpi_qualification_clock() returning clock_timestamp() (no client override; EXECUTE revoked for application roles). It exists as the isolated test seam for tied/backward-clock checks only; do not change host time. UTC canonical text must match Python isoformat: seconds when microseconds zero, otherwise exactly six digits, then +00:00. Reject outside years1..9999/nonfinite. Construct exact sorted canonical event object with the accepted version and hash. Insert all fields consistently. Receipt fields match the retained event; recorded_at is exact canonical text, independent of TimeZone and DateStyle. Retry does not resample time.

Apply RLS/privacy and UPDATE/DELETE/TRUNCATE refusal, including owner attempts, using accepted immutable-trigger conventions. Deny table/sequence writes and helper EXECUTE to PUBLIC, anon, authenticated, service_role; grant service_role SELECT on events and EXECUTE only on append RPC. Retain other modules' grants. Reapplying migration preserves rows, identities, sequence position and immutability. Never restart the sequence. Wrap invalid RPC errors in bounded static messages; source/command private text must not appear. The service role may submit administrative assertions, but cannot produce the future separately authorized execution verification. No claim that this RPC is a production qualification policy engine.
