# Validation result groups

Every performance result belongs to one exact combination of `data_source`, `strategy_version`, `model_version`, `evaluation_version`, `population_version` and `window_days`. A pair is a further grouping inside that combination. `ALL` may combine pairs only inside the same combination. It must never combine live and replay observations, model versions or scoring definitions.

Missing source or version metadata is labeled `unknown`; it cannot enter a known live or model group. Old rows keep `legacy-unversioned` scoring. A stored live label is not proof that its source vintage or publication timing has been audited.

The current scoring definition is `publication-snapshot-v2`, which binds each entry to original publication evidence and saves exact endpoint price evidence. Earlier `published-direction-v1` evaluations and their snapshots remain intact and separate. A legacy call without original price evidence has no v2 outcome; do not relabel its earlier result. See `docs/VALIDATION_PRICE_CONTRACT.md`. The current publisher in this checkout uses strategy `v2` and model `2.0-live`; default public live queries must select those exact values until an explicit model release updates both the publisher and public selection. Backtest version controls select `model_version`, not an inferred date range. No date cutoff is a substitute for `data_source`.

`window_days=0` means all available history through the stated as-of date. Positive values mean that many calendar days, inclusive of the as-of date; the first included date is as-of minus (window_days - 1). Snapshot storage keys include the entire combination, pair and as-of date. Query limits used for display must not limit the data behind aggregate metrics. Public aggregate recomputation requests `limit=null` and paginates until exhausted, using stable date/id ordering. Errors must remain errors or an explicit unavailable state, never a less restrictive fallback query.

Directional accuracy uses mature, finite market returns and boolean directional outcomes. Published NEUTRAL is an abstention; a directional forecast whose realized move falls in the deadband is WRONG. Pending or missing outcomes remain unavailable. Each metric displays its own denominator: total observations, eligible directional observations, net-payoff observations and probability-score observations are distinct. Confidence remains a heuristic unless held-out calibration evidence is supplied.

Raw market return and signed hypothetical payoff are separate fields. A mean signed gross payoff must not silently become a mean net payoff when a column is present. Neither overlapping call outcomes nor their cumulative sum defines a portfolio equity curve, Sharpe ratio or drawdown. Public pages must remove those unsupported representations and explain the available per-call results.

Readers now use `validation_observations`, a read-only view starting from every persisted `regime_calls` row. It left-joins the current canonical evaluation by `call_id`, never date/pair. The view exposes call identity, nullable evaluation identity and an explicit evaluation-present flag. Calls without a canonical evaluation retain null outcomes; their published direction, confidence and model metadata come from the original call.

`population_version=published-calls-v1` identifies this denominator. Existing snapshots default to `evaluation-records-v1` and remain separate; public queries require the new population version. `evaluation_version` on an unevaluated observation names the requested scoring definition, not evidence that an evaluation exists. The view uses PostgreSQL 15+ `security_invoker` so underlying caller permissions and row-level policies still apply.

Total calls includes pending calls, mature abstentions, unknown directions and missing evaluations. Evaluation count and missing-evaluation count sum to total calls. Those counts are independent of horizon maturity: a call may be immature and have no evaluation, or mature and have no evaluation. Scored share is eligible directional observations divided by total persisted calls in this group. Directional accuracy retains its narrower eligible-outcome denominator. Neither ratio proves that the scheduler published every expected session or that source inputs were available at publication time; those remain separate audits.
