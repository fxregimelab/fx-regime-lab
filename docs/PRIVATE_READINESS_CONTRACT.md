Revision 2, 1 October 2026. Previous goal turn made progress: the optional Jev adapter, authentic passage capture, direct verification and durable receipt were completed within their bounded implementation scope. The full research goal remains active. R2 source contracts still exclude unsupported historical availability; this packet advances R5 operating controls without changing that boundary. Revision2 distinguishes global report/context failures from pair-specific price failures so one stale pair does not veto unrelated fresh pairs.

The live API currently loads saved candidate fields without checking their age at request time. Add a pure readiness assessment and an authenticated response projection that holds stale/invalid candidates without rewriting report.json, history, AI, prices or ledgers. Readiness is an operational condition, not forecasting qualification. Even fresh data cannot promote a saved abstention.

## Shared interface

Worker owns only pipeline/src/private_desk/readiness.py, pipeline/tests/test_private_desk_readiness.py and reports/private-readiness-module-review.md. Define assess_readiness(report: dict[str, Any], *, now: datetime) -> dict[str, Any]. It reads no files, environment or network, does not mutate input and accepts only an offset-aware decision clock. Output is JSON-safe: method private-readiness-v1, checked_at UTC, status CURRENT/PARTIAL/HOLD, global_hold boolean, report_age_seconds or null, context_age_seconds or null, expected_completed_bar_date, reasons (global stable codes with plain text), pair_checks with pair/status/reasons/as_of/last_bar/weekday_lag. Global schema/universe/report/context/row-structure errors hold every candidate. Pair-only price errors hold that pair; otherwise fresh pairs remain current. PARTIAL means some pair checks pass and some hold; HOLD with global_hold false means none pass. Unknown or malformed source clocks cannot become zero age.

The report must have schema private-fx-v1, the exact seven-pair universe, exactly one report per pair and a valid offset-aware generated_at no later than now. Report age over 48 hours is a hold; equality is permitted. Current context uses current_context_updated_at, which must be offset-aware and no later than now. Missing/stale/invalid context is a hold even if the historical report was regenerated. No model success or source quality is inferred from a clock.

For daily price recency require data_coverage.status VALID, interval 1d, canonical as_of and last_bar date strings that agree. Require the latest completed UTC weekday: the previous UTC calendar day, walking backward across Saturday/Sunday. A date after that cutoff is incomplete/future; an older date is stale. weekday_lag counts weekdays strictly after the observed date through the expected cutoff, not calendar-day lag. This is a deliberately conservative operating rule for the existing date-only daily cohort. It does not certify the provider's FX session boundaries or exchange holiday calendar; holidays can produce a hold. Do not fabricate midnight availability or convert an observation date into a release timestamp. Missing/unavailable bars hold the pair. Dates must be real and canonical; duplicate, missing, foreign or malformed pair rows hold the global assessment.

Root owns pipeline/src/private_desk/api.py, pipeline/tests/test_private_desk_api.py, pipeline/tests/test_private_desk_readiness_api.py, reports/private-readiness-acceptance.md and reports/private-readiness-checks.txt and contract/ledger metadata. The first root claim refused overlap on TASK.md and private-desk/README.md with the earlier Jev leaf; remove those paths from this packet and leave them unchanged. The new receipt and parent contract/plan provide this checkpoint. Add operations_readiness to the browser response and age warnings to its existing warnings. If a global readiness hold applies, every live candidate projection becomes ABSTAIN and clears direction/entry/stop/tp1/tp2/probability/expected_r fields when present. Otherwise apply that hold only to pairs whose checks fail. Keep the saved report and historical fields unchanged. Status should show HOLD/PARTIAL with plain reasons while idle when readiness is held; active refresh progress remains identifiable. No API/key/order/AI behavior is broadened. Corrupt or unreadable current report produces a sanitized unavailable response, never a successful ready status or provider/source body leak.

Existing UI reads status.state/status and report warnings, and has a legacy candidate.bias direction fallback. Hold projection must also clear that bias, current probability/EV interval fields, and any execution_status flag. Idle status remains CURRENT/PARTIAL/HOLD even after a refresh error; a separate refresh_status and sanitized error retain that attempt's outcome. Structurally corrupt history/backtest/portfolio fields and conflicting trade-level pair identities fail report/export loading with sanitized unavailability. Trade exports always use the enclosing pair's identity. This packet adds no UI markup, idle polling or automatic refresh. Every report/status request rechecks the clock; an already open idle screen can retain its prior projection until reload, an explicit remaining display limitation. No dashboard timer or continuous live assurance is claimed.
