# Publication reader contract — repair packet ten

Storage preserves every publication. Current displays and inference state must choose intentionally among those records; validation must still evaluate the complete immutable population by call ID.

- Supported current publications are exactly EURUSD/USDJPY/USDINR, data_source=live, strategy_version=v2. Unknown legacy provenance and backtests cannot silently become current live calls.
- For a given pair/date, the greatest durable integer call ID is the latest appended live version. Order current calls by date descending then ID descending. History shows one latest live version per session, labeled with model/version; it is a revised publication history, not an independent forecast cohort.
- Public reads default to today's UTC date and exclude future dates. Python decision-state reads receive an explicit date cutoff. Prior-regime inference uses a strict earlier-session cutoff; same-day retry cannot feed its own output back into hysteresis. Descriptive current-day consumers may use inclusive cutoff. Paginate before deduplicating session history and applying its requested session count; a busy pair or many versions must not hide another pair or truncate a session window.
- A session-date cutoff alone does not prevent revised-history leakage. Prior-state reads also require the call's actual created_at to precede UTC start of the decision date; missing timestamps are ineligible for that path. This is a conservative daily convention until a full decision-timestamp contract exists. Later revisions of earlier sessions cannot enter earlier inference. Public retrospective history remains explicitly the latest revised history, distinct from historically available inference state.
- The new read-only public view public.live_publication_signals exposes only call_id integer, pair text, date date and signal_payload jsonb for live v2 locked-pair publications. It joins publication_evidence to regime_calls. It exposes no rationale, execution advice, write hash or correlation metadata. Anonymous/authenticated/service roles may SELECT; underlying evidence stays service-only. The view must not silently become writable.
- Public signal reads take the already selected call IDs and retrieve those exact immutable payloads. Routes must share one selected call set for call and signal rendering. Python explanations likewise read evidence by the selected call ID. A missing legacy snapshot means unavailable original inputs; do not substitute the current signals table. Preserve explicit UI wording for that missing state.
- Do not change get_historical_regime_calls semantics used by complete call-ID validation. Add distinct current-live read APIs where needed. Audit each latest/history consumer: prior state, regime age, AI context, daily summaries and shadow comparison. Filter and deduplicate before limits where needed. Readers must propagate query errors rather than returning a misleading empty healthy result.

Required evidence: future/backtest/unknown-source/cross-strategy contamination cases; multiple models on one date; many versions and paginated history; prior cutoff; exact signal ID despite newer projection; missing evidence; underlying validation population unchanged; public role permissions and view immutability in local PostgreSQL; frontend type/lint/build and complete pipeline regression. New inference model identifiers, broader point-in-time source repairs and release remain separate tracked requirements.
