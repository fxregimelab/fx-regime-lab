# FPI qualification order contract — v2

Parent-frozen implementation contract, packet 25. This repairs the pure qualification model needed by durable decision reads. The full repair goal, SQL transaction/visibility work, trusted execution and actual consumer integration remain required. Version 1 inputs/hashes retain their old meaning; no existing selector or published record is rewritten.

## Meaning and trust

A command expresses an intended state change with an expected predecessor. An event records the accepted command with an asserted server order and time. A head names the last event observed for one scope/target, or explicitly records absence. A resolution witness records the three qualification heads that justified choosing one dated membership at resolution time.

The pure module validates consistency of supplied evidence. It cannot authenticate a server, prove a complete database read or turn an arbitrary evidence hash into trusted execution. An ACCEPT state is a recorded qualification action, not permission to activate the feature. Actual consumption must additionally require a saved complete read, approved policy and verified parser/selector/normalizer execution. No database or provider access belongs in this module.

Explicit event ordinals order qualification transitions. Timestamps do not order them, including equal or decreasing clocks. The eventual SQL append protocol must supply these ordinals under one transaction-held qualification lock, fresh post-lock reads and predecessor checks. Standalone ordinals remain assertions. A clock inconsistency affecting source age must be handled separately by the future decision reader; do not adjust times or fabricate microseconds.

## Public interface

Create `pipeline/src/research/fpi_qualification.py`. Frozen dataclasses and exact canonical codecs are the interface; helpers stay private. All collections below are exact tuples. Hashes are lowercase 64-character SHA-256. Reject booleans where integers are required. JSON uses ASCII, sorted keys and compact separators with no duplicates, NaN, Infinity, NUL or surrogate strings. Decoders reject unknown/missing keys and noncanonical bytes rather than normalizing external documents. Builders normalize only documented set ordering and UTC datetime offsets.

- `FpiQualificationCommand(scope, target, action, reason_code, evidence_sha256, expected_prior_event_id=None, chosen_membership_id=None, basis_membership_ids=())`. Scopes: membership/value/parser/date. Non-date target is a hash and action is ACCEPT/WITHDRAW/QUARANTINE; chosen is null and basis empty. Date target is exact YYYY-MM-DD in years1..9999; action is RESOLVE, chosen is a hash and belongs to the nonempty unique basis of at most4096 hashes. Sort basis lexically. `reason_code` is `[A-Z][A-Z0-9_]{0,63}`. `evidence_sha256` is a reference only. No supplied ordinal or timestamp is a command field.
- Command `document_json` has exactly version=`fpi-qualification-command-v2` plus the eight fields above, with tuples as arrays. `command_id = sha256(canonical_document_bytes)`; version supplies the hash domain. Maximum command document300000 ASCII bytes.
- `FpiQualificationHead(scope, target, event_id)`, where event_id is a hash or None. Scope/target validation as above. Explicit absence must not be inferred from missing head records.
- `FpiResolutionWitness(heads)`: exactly three heads, one each membership/value/parser, sorted by `(scope,target)`. The membership head is non-null. Contextual checks against the chosen member and referenced events occur in the view.
- `FpiQualificationEventV2(command, event_ordinal, recorded_at, witness=None)`. Ordinal is exact int1..9223372036854775807. Time is aware datetime, converted to UTC, canonical ISO seconds or six-digit nonzero microseconds. RESOLVE requires a witness; non-date events require None. `document_json` exactly version=`fpi-qualification-event-v2`, command (nested command document object), command_id, event_ordinal, recorded_at, witness (null or object with heads array of exact scope/target/event_id objects). `event_id = sha256(canonical_document_bytes)`. Maximum event document400000 bytes.
- `decode_fpi_qualification_command(document_json)` and `decode_fpi_qualification_event(document_json)` rebuild and compare exact canonical documents. No I/O. Reject wrong primitive types, oversized/deep/duplicate/forged documents with bounded ValueError/TypeError, not leaked data.
- `FpiQualificationMember(membership_id, value_sha256, parser_sha256, reporting_date)`: all hashes exact, date exact `datetime.date` (not datetime). This is a compact asserted reference, never a substitute for the complete retained parse. The eventual loader verifies it against the accepted restore codec.
- `FpiQualificationView(members, heads, events)`: compact view over an explicitly supplied complete membership universe. `view_sha256` hashes a canonical object with version=`fpi-qualification-view-v2`, member records sorted by membership_id, heads sorted by (scope,target), and full event documents sorted by event_id. Date fields are ISO strings. Maximum20000 members,100000 heads,100000 distinct referenced events,16000000 canonical bytes. These are engineering rejection bounds, not evidence that operational resource sizing is complete. Empty universe requires empty heads/events.
- `evaluate_fpi_qualification(view) -> FpiQualificationEvaluation`: the main bulk evaluation interface. Validate/reconstruct the supplied view once; build current-action and date/member maps once. Return a frozen result with `view_sha256`, sorted `member_states` tuples `(membership_id,status)`, sorted `date_resolutions` tuples `(reporting_date,status,chosen_id_or_none)`, and `result_sha256`. The result hash binds canonical JSON containing version=`fpi-qualification-evaluation-v2` and the three other fields; dates are ISO strings. Output ordering is deterministic. No per-member full-view reconstruction or repeated full-data hashing. This avoids quadratic work when the future selector examines all candidates. The scalar helpers below are conveniences, not the future bulk consumer interface.
- `member_qualification(view, membership_id) -> str`: one of ACCEPTED, UNQUALIFIED, WITHDRAWN, QUARANTINED. QUARANTINED takes precedence over WITHDRAWN across any relevant scope, then membership absence gives UNQUALIFIED; otherwise membership ACCEPT is ACCEPTED. An ACCEPT on value/parser only clears that scope block; it never accepts a member by itself. Unknown membership rejects.
- `date_resolution(view, reporting_date) -> tuple[str, str | None]`: NO_RESOLUTION/None when the date head is absent; STALE_RESOLUTION/None when the head command basis differs from every supplied member on that date; TARGET_UNQUALIFIED/None when chosen member's current status is not ACCEPTED; RESOLVED/chosenID otherwise. Unknown date rejects. Explicit reinstatement can restore resolution usability when its basis is unchanged. A failed parse or missing date never acts as withdrawal.

## View validation

Validate sizes/types before sorting, hashing or repeated reconstruction. Reconstruct nested supplied dataclasses at the public view boundary: a frozen object is not an authenticity guarantee and can have been forged with object.__setattr__. Reject duplicate member IDs, duplicate head targets, duplicate event IDs, command IDs or ordinals, and contradictory metadata. In particular, one value hash cannot have different reporting dates, since its canonical INR value includes the date; the same value/date across multiple memberships/parsers is valid. Canonical ordering must make every input permutation identical.

Required heads are exactly the union of all member IDs, distinct value hashes, distinct parser hashes and distinct reporting dates in the supplied universe. Missing, additional or duplicate heads reject, including omitted explicit absence. All head references must resolve to a supplied event on the same scope/target. Every event command target must belong to that universe. A present predecessor, when also in the compact event set, must be a different earlier ordinal on that same scope/target. An absent predecessor is allowed: the database ledger owns full-chain validation. Do not fetch or demand unbounded historical ancestry. Duplicate successor roots/predecessors among supplied events reject.

For each RESOLVE event in the set: all basis IDs exist on the command date; chosen belongs to basis; its witness has the exact membership/value/parser targets from the chosen member. Each non-null witness references a supplied non-date event on its named target with ordinal strictly less than the resolution. The historical membership head must be ACCEPT; historical value/parser heads must be absent or ACCEPT. A witness naming a withdrawn/quarantined target rejects even if that target is accepted today. A witness claiming absent scope when any supplied earlier event on that scope exists is inconsistent and rejects; a witness head cannot be older than another supplied event on that target with ordinal below the resolution. This checks all available evidence without pretending missing chains are authenticated.

Current heads must be the latest ordinal among every supplied event for their scope/target; explicit absence is inconsistent with any supplied event on that target. Required event set is exactly all non-null current head IDs plus all non-null resolution-witness head IDs. No unrelated extra events, recursively imported full chains or guessed defaults. Historical witness events are non-date, keeping the reference graph shallow and bounded. Resolve those maps once; use sorted per-target ordinals or equivalent bounded work for historical consistency, not pairwise event scans.

The view binds both current and historical reference identities. A later withdrawal at the same or earlier wall clock does not invalidate the historical resolution witness. It changes current member status; the old saved view remains unchanged. A new same-date member makes the old resolution stale even when it is unqualified or from another parser. Broad value/parser blocks still compose with membership state.

## Required verification

1. Reproduce the v1 tied-clock counterexample, then demonstrate v2 ACCEPT -> RESOLVE -> WITHDRAW with all equal times and with decreasing times; old view remains resolved, new view is unqualified, and all permutations agree.
2. Explicit absence, missing/extra/wrong-target heads, forged nested dataclasses, duplicate/conflicting ordinal/command/identity, changed reason/evidence/target/basis/time/witness hashes, and noncanonical/unknown/oversized/deep JSON are tested.
3. Historical resolution witnesses reject then-blocked targets even after present reinstatement; present withdrawal cannot rewrite a valid past witness. Scope blocks compose, clearing one does not clear another, and explicit reinstatement follows the stated semantics.
4. Candidate addition returns STALE_RESOLUTION with complete same-date universe; same value across distinct member identities remains distinct. Alternate parser/value references are checked. Unknown members/dates reject.
5. Large historical predecessor values may be absent from a compact head view; a supplied wrong-scope/future predecessor or demonstrable fork rejects. No full-chain traversal. Batch evaluation must reconstruct once and traverse precomputed scope/date maps, never rehash the entire view per candidate. Exercise counts/bytes at relevant boundaries and show bounded work with long-history ordinals.
6. Independent parent reference comparison and deliberate wrong-state mutation must be capable of failing. Existing v1 suite stays unchanged and passes; full pipeline regression, Ruff and MyPy remain required.

FPI-T07 is closed only for the pure v2 model when these pass. Its durable counterpart remains open until real SQL proves order, isolation and complete saved reads. No production consumer switches versions in this packet.
