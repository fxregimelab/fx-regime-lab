# Durable FPI parse evidence

This layer retains implementation artifacts and complete parsed report results. It does not qualify an observation, execute retained code, prove source authenticity or establish historical decision visibility. The next layer must persist qualification transitions and exact committed decision reads. Original captures and old decisions remain immutable.

## Artifact retention

`build_fpi_artifact(*, kind: str, body: bytes) -> FpiArtifact` is pure. Kind is exactly `PARSER` or `SELECTOR`; body is 1 through 5,000,000 exact bytes, including arbitrary binary bytes. An artifact is a retained implementation bundle, not a mutable version label. Its SHA-256 is over the exact bytes. The bundle's packaging, dependency/configuration completeness and execution match require runner verification before qualification; storage must not claim those properties from a hash. Never execute uploaded artifacts in a storage function. Do not put credentials in artifacts.

The frozen `FpiArtifact` has `artifact_sha256` and `document_json`. The canonical ASCII JSON document has exactly `version` (`fpi-implementation-artifact-v1`), `kind`, `artifact_sha256`, `body_size` and `body_base64`. Use Python sorted compact JSON, ensure_ascii=True, canonical padded Base64 and lexical JSON integers. Maximum document size is 7,000,000 UTF-8 bytes. `validate_fpi_artifact` reconstructs and compares exactly before I/O.

Central writer `archive_fpi_artifact(artifact)` calls only `append_fpi_artifact(p_artifact_sha256 text, p_document_json text)`. The exact receipt is `{artifact_sha256, kind, inserted, stored_at}`. Identity/kind must match, inserted is a JSON boolean and stored_at is a finite UTC timestamp with zero through six fractional digits. A kind/hash pair identifies one immutable retained artifact. The same bytes may serve both kinds as separately declared records. Retry preserves the original stored_at.

## Complete parse records

`build_fpi_parse_record(parse: FpiParseResult, *, source_evidence_documents: tuple[str, ...]) -> FpiParseRecord` validates the supplied parse by reconstruction, not by trusting frozen dataclass attributes. The source documents correspond in order to the parse's already sorted dated memberships; no partial zip or silent truncation. Successful parses have 1 through 31 unique ascending dates. Failed parses have no days and no source documents. This storage version supports exactly `fpi-inr-observation-v1`; future definitions require an explicit extension. Failure reasons are bounded machine codes matching `[A-Z][A-Z0-9_]{0,63}`, never raw exception text.

`FpiParseRecord` has `parse_id`, `record_sha256`, and `document_json`. record_sha256 hashes the exact ASCII document. Its exact fields are `version` (`fpi-parse-record-v1`), `parse_id`, `content_sha256`, `capture_sha256`, `parser_sha256`, `definition_version`, `recorded_at`, `failure_reason`, and `days`. Use sorted compact ASCII JSON. Each day has exactly `reporting_date`, `value_sha256`, `membership_id`, `document_json`, `source_evidence_sha256`, and `source_evidence_document_json`.

The canonical INR document and all existing pure identities remain unchanged. parse_id, content_sha256 and membership_id must equal FpiParseResult's existing definitions. The source evidence document must match the member's hash and date. It has the existing `nsdl-fpi-source-evidence-v1` schema: exact seven categories/routes, USD_MILLION, INR_PER_USD, positive four-decimal conversion rate, exact two-decimal net values and the parser's child/subtotal/total rounding bounds. Preserve USD values independently; never reconstruct them from INR. Canonical INR validation retains nonnegative gross amounts and every current reconciliation bound. Documents are at most32,768 characters each; the complete encoded record is at most4,000,000 bytes. Reject duplicate keys, NUL, lone surrogates, unknown fields, wrong primitive types, noncanonical money/date/version and malformed hashes before client access.

`restore_fpi_parse_record(record: FpiParseRecord, capture: FpiCapture) -> FpiParseResult` validates exact record/capture identities, rebuilds the existing dataclasses and checks the entire canonical record by reconstruction. Capture bytes stay in their existing table. Source evidence stays in the record for exact readback. A failed or altered readback must never become a selector input.

Central writer `archive_fpi_parse_result(parse, *, source_evidence_documents)` builds and validates before client access and calls only `append_fpi_parse_result(p_parse_id text, p_record_sha256 text, p_document_json text)`. It does not implicitly archive capture or artifact dependencies. Receipt is exactly `{parse_id, record_sha256, content_sha256, membership_ids, inserted, stored_at}`; membership_ids match the complete ascending-date list, without missing, additional or reordered entries. stored_at must be finite UTC, with no excess precision, and not precede parse.recorded_at. Return detached data; sanitize transport/provider errors without echoing source bodies, supplied JSON or exception chains.

## Database contract

Forward migration `20260927000011_fpi_parse_storage.sql` depends on the accepted capture migration. Create private append-only `fpi_implementation_artifacts`, `fpi_parse_results`, and `fpi_parsed_memberships`. Artifact key is `(kind, artifact_sha256)`. A parse references an existing capture and existing PARSER artifact; SELECTOR alone is insufficient. Store authoritative exact envelope text and derived fields. Memberships reference the parse and retain exact INR/source documents, hashes, reporting date and membership identity. Index reporting date, value hash and capture/parser identity for the later complete decision reader. No first-seen or availability field is inferred.

Direct SQL entry points validate the same structural, identity, numeric, size, timestamp and dependency rules without trusting the Python client. Preserve all hash definitions exactly. SQL must reject duplicate keys before JSONB conversion, lexical number substitutions, forged IDs/content hashes, mismatched source dates, partial/failing mixtures, duplicate dates and future recording times. Retain canonical text so semantic reserialization cannot change identity. Helpers may reuse capture helpers without changing their interface or privileges; new helpers are private, bounded and use fixed search_path. JSON canonicalization must agree with Python for the permitted schema, including embedded document strings.

One parse RPC transaction inserts the complete result and all memberships or none. Exact concurrent retries return one retained result, complete identical membership_ids and identical stored_at. A changed result or recording time under one parse identity is a conflict; never silently overwrite or accept whichever text was most recently submitted. A losing malformed/conflicting request leaves all prior records unchanged. References to absent dependencies fail atomically.

Apply the capture layer's explicit grants, RLS and UPDATE/DELETE/TRUNCATE protection to every new table, including owner mutation checks. PUBLIC/anon/authenticated have no access; service_role has narrowly granted SELECT and entry-point EXECUTE, with no direct writes or helper execution. SECURITY DEFINER functions have fixed search_path and sanitized errors. Reapplication preserves populated records and unrelated table/role permissions. No original calls/evaluations or public tables change.

stored_at is assigned inside a transaction and is not commit time. Verification must pause a real writer transaction, confirm a concurrent reader sees neither parse nor memberships, commit it, and confirm both become visible together. This proves this layer's atomic visibility only; saving a full qualified decision read, reverse-commit decision reconstruction and consumer parity remain required in the next layer.
