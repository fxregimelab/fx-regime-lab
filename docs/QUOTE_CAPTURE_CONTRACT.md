# Quote capture and construction contract — packet 14

Implements the deterministic capture/constructor layer of the accepted primary-source acquisition design. Packet 15 separately implements and locally verifies durable capture/snapshot storage under QUOTE_STORAGE_CONTRACT.md. Actual HTTP pagination, acceptance-event policy and evaluation integration remain required; this pure-layer contract does not claim those implemented. No provider request is necessary for its tests. No observation qualifies for validation from this layer alone.

## Shared Python interface

Parent owns `src/research/quote_capture.py`:

- `canonical_json(value: Any) -> str`: deterministic strict JSON; preserve arbitrary integer/numeric precision with Decimal for fractional JSON numbers; sorted object keys; no NaN/Infinity, non-string keys or unsupported values. Numerically equal finite representations normalize equally; JSON numbers and strings remain different. No float timestamp conversion.
- `capture_quote_page(*, pair: str, instrument: str, window_start_ns: int, window_end_ns: int, page_index: int, requested_at: datetime, received_at: datetime, status_code: int, body: bytes, request_params: Mapping[str,str], response_headers: Mapping[str,str], secrets: Sequence[str] = ()) -> dict[str,Any]`.
- `validate_quote_page(page: Mapping[str,Any]) -> None`: reject malformed/tampered manifests before construction. Capture fields below are exact. Validation does not reconstruct redacted original bytes or certify provider authenticity.

Worker owns `src/research/quote_reference.py`:

- `build_quote_reference(pages: Sequence[Mapping[str,Any]], *, as_of: datetime) -> dict[str,Any]`.
- Pure function. No reads, writes, current clock, provider calls or environment access. Empty page collection or malformed manifest raises ValueError. Data/acquisition defects instead produce explicit provisional diagnostics and never a qualified bar.

## Page manifest

Exact fields: `version` (=quote-page-v1), `provider` (=massive), `pair`, `instrument`, `window_start_ns`, `window_end_ns`, `page_index`, `request_parameters`, `request_cursor_sha256`, `requested_at`, `received_at`, `http_status`, `response_headers`, `body_text`, `raw_body_sha256`, `body_sha256`, `raw_size_bytes`, `next_cursor_sha256`, `issues`, `capture_sha256`.

Locked pairs only. Instrument must equal the explicit candidate form C:EUR-USD, C:USD-JPY or C:USD-INR for that pair; this validates request consistency, not actual provider availability. Caller supplies instrument. Window is exactly one UTC day, aligned to the Unix epoch with integer nanosecond bounds, represented as canonical decimal strings in the manifest; require 0 <= start < end and end-start = 86400000000000. page_index is a nonnegative integer (never bool). All timestamp arguments are aware; stored dates use UTC ISO strings. Receipt must not precede request. Status is integer 100..599, never bool. Body limit is 16 MiB; oversized bodies raise before capture (transport must eventually enforce the streaming limit too).

Initial request must contain exactly timestamp.gte, timestamp.lt, sort, order, limit (plus sensitive keys, which are discarded); timestamp strings equal window bounds, sort=timestamp, order=asc, limit is a canonical integer 1..50000. Later pages require cursor and may repeat only the same valid fixed fields. Cursor never appears in retained manifests/body: persist its SHA-256, not the opaque token. Only normalized nonsensitive request parameters are retained. API keys, tokens, cookies and authorization values are never retained. Secret-key names normalize by removing underscores/hyphens and case-folding. The known-secret list also removes literal and URL-encoded forms wherever they occur in retained text. Keep response headers only content-type and x-request-id, sanitized. A manifest is not a security claim about unspecified unknown secrets in arbitrary provider content; production capture needs the reviewed source schema and configured secret list.

Decode UTF-8 strictly. For invalid UTF-8, retain sanitized replacement-decoded text and issue invalid_utf8. Parse JSON strictly (reject duplicate keys and NaN/Infinity). Invalid JSON is retained as sanitized text with invalid_json. JSON bodies are retained with canonical numeric precision. Sensitive object fields are replaced with [REDACTED]. next_url is reduced to a safe provider URL with its opaque cursor redacted; its original cursor hash is separate. Allowed next origins are HTTPS api.massive.com/api.polygon.io, no userinfo/port/fragment, exact quote path for the instrument (percent-encoded path is accepted only after exact decoding); query keys are cursor, optional fixed request fields, and sensitive keys discarded. Duplicate query keys, missing/blank cursor, inconsistent fixed fields, foreign origin/path, malformed URLs produce invalid_cursor and no trusted next hash. Missing/null next_url means terminal. Never follow a URL in this pure module.

Hashes are lowercase SHA-256 hex: raw_body_sha256 over original bytes; body_sha256 over sanitized body_text UTF-8; capture_sha256 over canonical_json of every other manifest field. raw_size_bytes counts original bytes. Empty or altered capture hashes fail validation. Original bytes are not retained. Fingerprints prove internal consistency, not authenticity. Store issues in deterministic order without raw exception messages.

## Constructor

Validate every manifest first. Require consistent pair/instrument/window, page indices 0..N-1, first request cursor null, later cursor hashes matching the previous next hash, all receipts <= as_of, monotonically nondecreasing request/receipt acquisition order, and each request at or after preceding receipt. Record defects (not an assumed complete run) for HTTP !=200, manifest issues, invalid body/schema/status, missing last page, duplicate page hashes, broken cursor chain/cycle and out-of-order pages. Never construct OHLC from an incomplete acquisition prefix. Require body JSON object with status=OK and results a list; results may be absent only as invalid_schema (do not infer an empty successful result). Preserve complete page hashes in ordered input lineage.

For a complete acquisition, retain every source occurrence in the captured body. Count occurrences separately from distinct canonical row signatures. A valid quote is an object with integer participant_timestamp (not bool) and finite positive JSON numeric bid_price/ask_price (not bool/string), with bid <= ask. Exchange IDs and other source fields are retained, not used as a unique event identity. Timestamp membership is half-open [start,end); no timestamp float conversion. Count invalid and out-of-window occurrences explicitly. Midpoint uses exact Decimal arithmetic with adequate local precision; serialize prices as canonical decimal strings. Repeated equal rows do not change OHLC; report duplicates but never remove original occurrences. Distinct midpoints at the earliest/latest timestamp make open/close respectively null and ambiguous; do not use page order to break ties. High/low are extrema across all valid in-window midpoints. A malformed or out-of-window quote makes the candidate ineligible and is visible; valid-subset statistics may remain as diagnostics for a complete acquisition.

Result fields must include series_id=massive-fx-bbo-mid-utc-v1, algorithm_version=quote-midpoint-utc-v1, pair, instrument, window_start_ns/end_ns, as_of UTC, ordered capture_sha256 list, input_sha256 binding algorithm and full ordered capture hashes, acquisition_complete bool, source_occurrence_count, distinct_row_count, duplicate_count, unique_timestamp_count, invalid_occurrence_count, out_of_window_count, first_timestamp_ns/last_timestamp_ns, first_event_offset_ns/last_event_age_ns (integers serialized as decimal strings or null), open/high/low/close (decimal strings or null), ambiguous_open/ambiguous_close, exclusion_reasons, provider_finality=unknown, project_maturity=provisional and validation_eligible=false.

Always include coverage_policy_unverified in exclusions: no empirical boundary-age, holiday or revision rule is accepted yet. Other stable reasons describe observed defects. Compute source/timing metrics only from complete acquisition data; incomplete runs return null OHLC and explicit counters without presenting a prefix as a daily reference. No endpoint substitution, price interpolation, daily-provider fallback, market-volume or executable-price claim. As-of time is part of the result but not source fingerprint; the same captures/algorithm have the same input hash.

## Acceptance

Packet-15 storage amendment: actual NUL and lone-surrogate characters in JSON string values/keys, retained malformed text and allowed header values become visible literal backslash-uXXXX sequences. Any replacement adds `text_storage_escaped` after `non_integer_quote_timestamp` in issue order. Source numeric values remain exact; exceptional source strings/keys are explicitly sanitized, not claimed lossless. Original byte hash and size stay unchanged. A key collision after sanitation rejects capture. The validator rejects forged unrepresentable outer text or unsupported strings inside otherwise valid body JSON. Malformed-original diagnosis remains even if retained text becomes parseable. These diagnosed captures produce incomplete, validation-ineligible references.

Parent-reviewed amendments from integration checks: the ordered output hash-list field is named `capture_sha256`. A source timestamp expressed as a fractional/exponent JSON token, string or bool raises the capture issue `non_integer_quote_timestamp` before numeric canonicalization; normalization must never disguise its original type. Cursor values are redacted from value text, while schema key names are preserved if they merely overlap an opaque cursor. Known configured secrets still redact keys and values; a collision of redacted keys rejects capture rather than silently merging fields.

Exact arithmetic has an explicit resource envelope: a price may have at most 128 coefficient digits and its Decimal exponent and adjusted exponent must each lie in [-128,128]. Values outside this envelope remain in the captured source but count as invalid quote occurrences, with a numeric-limit exclusion. This is a software resource limit, not an empirically accepted price-quality rule. It prevents tiny response bodies from requesting unbounded exact-arithmetic output. Within the envelope, calculation must remain exact and independent of the process Decimal context.

A complete daily acquisition must begin every page request at or after the window end, and the window must have ended by `as_of`. Earlier acquisition is explicitly incomplete and yields no daily OHLC, even if pagination terminated. Repeated fixed request fields on later pages must agree with the first page, including limit. These checks prevent a fully traversed intraday prefix from being presented as a completed daily reference; they do not establish provider finality.

Capture tests: secret keys/literal/encoded forms, opaque cursor handling, hostile next URLs, exact precision, duplicate JSON keys, malformed UTF-8/JSON, bounds/types, detached immutable inputs and hash tampering. Constructor tests: exact nanosecond UTC boundary, truthful empty snapshot, missing/failing/cyclic pages, reordered/tampered captures, late receipt, invalid/crossed quotes, exact decimal midpoint, timestamp ties, duplicate occurrences, corrections producing new hashes while preserving old outputs, three-pair consistency and no eligibility from mere completion. Tests use synthetic quotes only and cannot count as observed market evidence.
