# Validation price evidence contract

Packet 11 evaluates the movement from the exact published signal snapshot to a stored historical close. It is not an executable trading return. Publication times, market holidays, financing and observed execution costs remain separate research requirements.

- New evaluation version: `publication-snapshot-v2`. Preserve all older `published-direction-v1` rows and statistics unchanged. Current population readers request only the new version; older calls without original evidence remain visible as missing evaluations.
- Entry: `publication_evidence.signal_payload.spot` for the exact durable call ID. Signal pair/date must match the call. Missing original evidence means no new evaluation; never substitute mutable signals, another version, an ingestion window or a later downloaded entry.
- Endpoint: only `historical_prices.close` for the exact pair and weekday-horizon date. No nearest-earlier, future, live-provider or snapshot fallback. Missing endpoint means that horizon remains unavailable. Capture the selected price and identity in immutable evaluation JSON.
- Fields: `entry_price_evidence`, `price_evidence_t5`, `price_evidence_t20`. Each is an object containing exactly `kind`, `pair`, `date`, `price`, `source`; entry also contains `call_id`. Entry kind/source are `publication_signal` / `publication_evidence.signal_payload.spot`; endpoint kind/source are `historical_close` / `historical_prices.close`. Dates are strict ISO calendar dates; prices are finite positive JSON numbers, never booleans. Unknown provider/release timestamps are not invented. This records the storage origin, not proof of original provider provenance.
- Completed horizon values and their evidence cannot change. A later endpoint correction does not rewrite an existing evaluation. Existing entry evidence is preserved. Idempotent retries produce no new row. New horizons append a revision while preserving completed horizons. Fully complete/not-yet-due calls return before price reads.
- Database verifies entry against immutable publication evidence, evidence identities/dates, finite numbers and metric consistency with the stored prices, published direction/confidence and fixed research cost/deadband assumptions. Concurrent calls remain serialized, permissions restricted and rollback atomic. Old-version append semantics remain available only as their original version; new application writes use v2.
- Shared pure interface in `src.validation.evaluator`: `evaluate_call(call, as_of, existing, *, read_entry, read_price) -> dict[str, Any] | None`. Call accepts `id` or `call_id` (must agree if both present). Callbacks: `read_entry(call_id) -> signal dict | None`; `read_price(pair, target_date: date) -> historical row dict | None`. Current-version existing row must match call ID/version. No I/O inside evaluator beyond supplied reads. Shared weekday calendar and calculator remain authoritative. Invalid/missing call or evidence yields no scored row with an honest log; database/network errors propagate.
- Writer interfaces: existing `get_publication_signal_for_call(call_id)` and new `get_exact_historical_price_for_date(pair, date_str)` (strict exact-date query, no fallback). All four scoring paths use the shared evaluator and these evidence sources. Staged writer port exposes matching reads, independent of its 120-day ingestion snapshot. Backfill dry runs remain read-only; no raw private PostgreSQL connection or unverified TLS is needed for validation replay.

Acceptance: two same-date versions with different spots produce different returns from their own entries despite contradictory mutable prices; legacy missing evidence stays missing; stale/wrong-date/nonfinite data cannot score; old backlog works without ingestion bars; partial completion freezes T5 plus evidence while adding T20; completed retries do not fetch prices; SQL rejects changed evidence/metrics, preserves v1, isolates v2 cohorts, serializes concurrent retries and rolls back failure.
