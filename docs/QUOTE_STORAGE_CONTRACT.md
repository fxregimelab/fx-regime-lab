# Immutable quote storage contract — packet 15

This extends the packet-14 pure capture/constructor contract with private durable records. It does not qualify prices or implement provider transport. Existing calls, evaluations and historical_prices must remain unchanged. All application writes go through pipeline/src/db/writer.py.

## Page storage

Python `archive_quote_capture(page: Mapping[str,Any]) -> dict[str,Any]` validates the complete quote-page-v1 manifest, detaches it, serializes all fields except capture_sha256 using canonical_json, and calls exactly one RPC:

`append_quote_capture(p_capture_sha256 text, p_unsigned_json text)`.

The hash must equal lowercase hex SHA-256 over exact UTF-8 p_unsigned_json. The unsigned document contains exactly the packet-14 page fields excluding capture_sha256. Persist the original unsigned text as well as an inspectable parsed JSON representation. The text is authoritative for the fingerprint and reconstruction; PostgreSQL JSONB formatting must not be substituted for Python canonical serialization. SQL proves exact bytes/hash and structural invariants, not that an arbitrary service-role caller used Python's canonical serializer. No original credential-bearing response bytes are stored.

Private table `quote_captures` uses capture_sha256 as primary key. Store pair, instrument, window bounds, receipt and database stored_at for indexed retrieval, derived from the validated document. Window bounds are exact integer numeric/text, never float. Identical retries return the same hash; a conflicting retained payload for an existing hash raises. Corrections append a new capture. Receipt may not be in the database's future. The current day need not be closed for archival: incomplete/intraday evidence is useful and remains unqualified.

Page RPC receipt has exactly `capture_sha256` and `inserted` (JSON boolean). Python rejects any extra/missing field, wrong hash or non-bool status. Malformed caller data fails before client acquisition. A serialized page above 32 MiB fails before RPC; SQL enforces the same UTF-8 byte bound. Raw source bytes still have the packet-14 16 MiB limit; redaction/escaping can increase representation size and must never be silently truncated.

SQL validates exact keys; pair/instrument lock; one aligned UTC day; integer index/status/size; required timestamp types, timezone and ordering; permitted headers and request parameters; cursor hashes/nullability; known issue codes/order/uniqueness; body hash; raw hash shape; and next-cursor/body consistency where body is valid JSON. An invalid body can be archived only with invalid_json. Body numerical/source qualification remains the constructor's responsibility; malformed source is preserved as diagnosed evidence. Huge JSON numeric exponents in body_text must not crash SQL parsing: bodies stay TEXT and failure to represent them as JSONB is not treated as loss of the captured original text or a new market-quality decision. SQL may use JSON rather than JSONB when inspecting body shape. Every SQL error omits source bodies, cursor tokens and credentials.

Storage review amendment: actual NUL and lone-surrogate characters cannot be materialized by PostgreSQL text/JSON inspection. Capture replaces them in JSON string values and keys, malformed raw-text diagnostics and allowed header values with visible literal backslash-uXXXX sequences. Any replacement adds the stable issue `text_storage_escaped`, ordered after `non_integer_quote_timestamp`. Source numeric values and recognized field names remain unchanged. Exceptional source strings/keys are sanitized, not claimed lossless; original response-byte hash and size remain unchanged. A key collision after sanitation rejects capture rather than losing fields. Every affected reference stays incomplete/ineligible. The pure validator rejects forged manifests retaining unsupported actual characters or unsupported strings inside otherwise valid body JSON. This explicit diagnosis preserves sanitized failure evidence without weakening SQL validation or promoting transformed data.

## Snapshot storage

Python `archive_quote_snapshot(pages: Sequence[Mapping[str,Any]], *, as_of: datetime, implementation_sha256: str, client_version: str) -> dict[str,Any]` computes build_quote_reference from the supplied pages, validates the provenance labels, and sends:

`append_quote_snapshot(p_snapshot_sha256 text, p_unsigned_json text)`.

The exact unsigned snapshot fields are `version` (=quote-snapshot-v1), `implementation_sha256` (64 lowercase hex), `client_version` (1..128 characters, ASCII letters/digits/dot/underscore/hyphen only), and `reference` (the exact build_quote_reference result). Hash is SHA-256 of exact canonical unsigned JSON UTF-8. The caller-supplied implementation hash and client label are provenance assertions; storage cannot certify that those bytes actually executed. A future acquisition runner must compute and preserve its real implementation artifact. Tests use explicitly synthetic labels.

Private table `quote_snapshots` uses snapshot_sha256 as primary key. Store authoritative unsigned text and parsed JSON plus derived pair/window/as_of and stored_at. The RPC requires every referenced capture already exists and preserves its exact ordered hashes through private `quote_snapshot_pages(snapshot_sha256, ordinal, capture_sha256)` rows. No cascade may mutate/delete a capture, snapshot or membership. The entire snapshot and membership insertion is atomic. Missing capture, inconsistent page identity, invalid input hash or malformed envelope rejects without a partial snapshot. The snapshot writer does not upload missing pages implicitly: callers archive each response as received, then append a terminal snapshot, preserving partial durability if a later page or snapshot fails.

Reference exact fields are those returned by packet 14. SQL verifies required types, fixed series/algorithm/version identifiers, validation_eligible=false, project_maturity=provisional, provider_finality=unknown, coverage_policy_unverified in exclusions, and as_of not in the database's future. Verify the ordered capture list against existing pages and identity/window. Verify input_sha256 independently over the canonical object with algorithm_version then capture_sha256 keys, matching the constructor. Store incomplete diagnostic snapshots too; never infer qualification from complete pagination. The SQL layer does not independently recompute midpoint arithmetic or every diagnostic counter; the parent must prove Python constructor-to-writer-to-SQL round-trip equivalence. Accepted price/evaluation policy is a separate required layer, with no read path promoting these records into historical_prices.

Snapshot RPC receipt has exactly `snapshot_sha256`, `inserted` (bool), `capture_count` (integer, never bool; equals ordered input count). Python fails on malformed receipt. Snapshot unsigned JSON is limited to 1 MiB and 1..10000 page hashes, with matching Python/SQL limits. Repeated hashes can be retained in an incomplete snapshot as evidence of a duplicated-page defect; ordinal preserves every occurrence. Pair/window inconsistencies cannot be stored in one snapshot and must remain separate captures rather than receive a misleading snapshot identity.

## Access and verification

Append-only UPDATE/DELETE/TRUNCATE triggers protect all three tables, including owner operations. RLS is enabled. Anonymous and authenticated roles have no table, sequence or function access. Service role has SELECT plus exact RPC execution, no direct INSERT/UPDATE/DELETE/TRUNCATE. Functions are SECURITY DEFINER with fixed pg_catalog/public search_path; helpers are not public entrypoints. Grant no EXECUTE to PUBLIC and do not broaden existing unrelated grants.

Use forward idempotent migration 20260927000008_quote_capture_storage.sql. Reapplication preserves data. Prove fresh isolated PostgreSQL creation, reapplication, exact retries, concurrent retries, atomic snapshot rollback, strict schema/hash/type checks, permissions, mutation refusal and original-table preservation. Verification must exercise actual Python capture/constructor/writer serialization into SQL, not only handwritten JSON. Use the task-local socket-only PostgreSQL; no production credentials or provider requests. Parent starts and verifies the runtime, and stops it after all checks.
